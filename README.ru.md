# Contract-Driven Development

**Три фазы, три артефакта. Рабочий процесс для пары «человек + AI-агент», где узкое горлышко — не скорость агента, а время человека на проверку.**

## Проблема

Агент генерирует что угодно за секунды. Стандартный паттерн — «план → утверждение → исполнение» — ломается на шаге «утверждение». Агент пишет план на 1000 строк. Вы читаете, думаете «бля, всё не то», и час жизни уходит.

**Корень проблемы**: читать чужой текст трудно. Отвечать на конкретный вопрос — легко.

## Решение

Агент не пишет вам. Агент спрашивает вас. Вы отвечаете коротко. Агент работает автономно в заданных границах.

```
Фаза 1: Контракт     → 5 вопросов, 20 строк YAML
Фаза 2: Карта        → 200–300 слов, проверка направления
Фаза 3: Имплементация → слайсы, авто-продолжение на зелёных тестах
```

Вы касаетесь процесса три раза:
1. Ответили на 5 вопросов (2 минуты)
2. Глянули карту, сказали «ок» (15 секунд)
3. Заглянули на красный слайс (редко)

## С чем работает

### Claude Code — первоклассная поддержка

Один файл — и команда `/contract` готова:

```bash
cp adapters/claude-code/contract.md .claude/commands/contract.md
```

Клод задаёт 5 вопросов, пишет контракт, рисует карту и работает слайсами с авто-продолжением. Контракты сохраняются в `.claude/contracts/`.

### Другие агентские harness-ы

Методология не привязана к конкретному инструменту. Ключевой артефакт — YAML-контракт. Любой агент, умеющий читать файл и следовать инструкциям, может работать по этой схеме.

| Harness | Как подключить |
|---------|---------------|
| **Hermes Agent** | Встроенный скилл: `skill_view(name='contract-driven-development')`. Контракты в `.hermes/contracts/`. |
| **Cursor** | Напишите контракт вручную, добавьте в `.cursorrules`: «Прочитай `.cursor/contracts/current.yaml` перед началом. Если решение выходит за границы — спроси, не продолжай.» |
| **Aider** | Добавьте путь к контракту в `read:` файла `.aider.conf.yml`. Используйте `/read-only` для файлов из `boundaries`. |
| **OpenHands / Devin** | Передайте контракт как `instructions` в конфиге задачи. Агент читает границы перед генерацией плана. |
| **GitHub Copilot** | Включите YAML-контракт в тело issue. Copilot Workspace читает его как спецификацию. |
| **Любой агент с доступом к файлам** | Положите контракт в репозиторий. Добавьте правило: «Прочитай `.contracts/<task>.yaml` перед началом.» |

### Почему Claude Code — лучшая посадка

Кастомные слеш-команды (`/contract`) поддерживают интерактивные многошаговые диалоги. Адаптер в этом репозитории даёт полноценный диалог: агент спрашивает, вы отвечаете, контракт формируется органически.

Для других harness-ов без кастомных команд вы пишете контракт самостоятельно (используя шаблон) и передаёте как ограничение. Методология держится: поверхность утверждения сжимается с «плана на 1000 строк» до «YAML-а на 20 строк».

## Фаза 1: Контракт

Агент не пишет план. Агент задаёт 5 структурированных вопросов:

| # | Вопрос | Поле в контракте |
|---|--------|-----------------|
| 1 | Что нельзя трогать? | `boundaries` |
| 2 | Что должно остаться правдой? | `invariants` |
| 3 | Как поймём что готово? | `acceptance` |
| 4 | Какие библиотеки/паттерны использовать? | `style` |
| 5 | Что случилось и почему сейчас? | `context` |

На выходе — YAML на 20–30 строк. Человек утверждает контракт, а не план.

## Фаза 2: Карта

Агент по контракту рисует карту. 200–300 слов. Twitter-формат:

```
Map: Добавить экспорт отчётов в CSV

Files:
  src/export/csv.go        — modify: add ExportToCSV method
  src/handlers/reports.go  — modify: add GET /reports/export
  tests/export_test.go     — new: 12 test cases

Flow:
  HTTP GET → handler → CSV builder → file download

Tests:
  unit: ExportToCSV edge cases (empty, unicode, large)
  integration: handler returns 200 + valid CSV

Order:
  1. ExportToCSV method
  2. Handler endpoint
  3. Tests
```

Человек проверяет одно: правильное ли направление?

## Фаза 3: Имплементация с чекпоинтами

Агент режет работу на слайсы. После каждого слайса:

```
Слайс → тесты → зелёные? → авто-продолжение
                    ↓ нет
               Стоп. Человек смотрит.
```

Человек вмешивается только когда тесты красные или агент упёрся в решение, не покрытое контрактом.

## Почему это работает

| Обычный подход | Contract-Driven |
|---|---|
| Агент пишет план (легко) | Агент задаёт вопросы (легко) |
| Человек читает план (тяжело) | Человек отвечает на вопросы (легко) |
| Агент исполняет (легко) | Агент исполняет в рамках контракта (легко) |

Асимметрия развёрнута в пользу человека.

## Ближайшие аналоги

- **Shape Up (Basecamp)**: pitch → scope → build. Компактные документы, явные границы.
- **TDD**: тесты как контракт, red-green-refactor как чекпоинты.
- **Dependabot/Renovate**: авто-мёрж на зелёном CI, человек вмешивается только на красном.

Contract-Driven Development собирает эти идеи в агентный воркфлоу.
